# 版本更新规则

本文件描述 CCLoader 烧录器的版本号规范和发版流程。

## 版本号规范

采用 [语义化版本](https://semver.org/lang/zh-CN/)（SemVer），格式为 `vX.Y.Z`：

| 版本段 | 含义 | 何时递增 | 示例 |
|--------|------|----------|------|
| **主版本** (X) | 重大架构变更、不兼容修改 | 接口/协议重构、不向后兼容 | v0 → v1 |
| **次版本** (Y) | 新增功能、向后兼容 | 新增 API、新功能模块 | v1.2 → v1.3 |
| **修订号** (Z) | BUG 修复、小调整 | BUG 修复、文案/样式微调 | v1.0.0 → v1.0.1 |

> 说明：当前 CCLoader 历史版本采用两段式 `vX.Y`（修订号为 0 时省略），待首次出现仅修复 BUG 的发版时启用三段式 `vX.Y.Z`。

## 发版判定标准

- **需要发版**：修复 BUG 或增减功能后编译烧录，即为一次发版，必须更新版本号。
- **不需要发版**：仅修改文档、注释、开发环境配置等不影响固件行为的改动。

## 版本号位置

CCLoader 的版本号需在两处同步维护：

| 位置 | 文件 | 内容 |
|------|------|------|
| 位置 1 | `data/index.html` | `<div>固件版本: CCLoader-WebUI vX.Y</div>` 字符串（位于"设备信息"卡片） |
| 位置 2 | `src/web_assets.h` | 由 `tools/gen_web_assets.py` 从 `data/index.html` 自动生成的静态资源 |

**强制规则**：修改 `index.html` 后必须运行 `python tools/gen_web_assets.py` 重新生成 `web_assets.h`，否则 OTA 升级固件时 WebUI 不会同步更新。

## 发版更新清单

每次发版按以下清单依次执行：

| 序号 | 操作 | 说明 |
|------|------|------|
| 1 | 编辑 `data/index.html` | 更新 `固件版本: CCLoader-WebUI vX.Y` 字符串为新版本号 |
| 2 | 运行 `python tools/gen_web_assets.py` | 重新生成 `src/web_assets.h` |
| 3 | 编辑 `CHANGELOG.md` | 将新版本条目从 `[Unreleased]` 移至 `[X.Y]` 并填写日期 |
| 4 | 编辑 `Documents/项目进展.md` | 更新"当前状态"中的版本号 |

## CHANGELOG.md 规范

- 遵循 [Keep a Changelog 1.1.0](https://keepachangelog.com/zh-CN/1.1.0/)。
- 版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。
- 变更分类：

| 分类 | 含义 |
|------|------|
| **新增** | 新增的功能、API、模块 |
| **变更** | 对已有功能的修改、行为调整 |
| **修复** | BUG 修复 |
| **版本号** | 记录版本号迁移（如 `v1.2 → v1.3`） |

- 文件底部维护版本比较链接，新增版本时添加对应的 `compare` 链接，格式：

```markdown
[X.Y]: https://github.com/wedone/CCLoader/compare/vX.Y...vX.Y
```

- `[Unreleased]` 段始终保留于顶部，用于累积下一个版本的未发版变更。

## AI 操作准则

修复 BUG 或增减功能后编译烧录前，必须先按"发版更新清单"完整更新版本号及相关文档（`index.html` → `web_assets.h` → `CHANGELOG.md` → `项目进展.md`），不得跳过任何一步。仅修改文档时可不必递增版本号。

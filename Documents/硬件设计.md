本文件描述 CCLoader 烧录器的硬件设计、引脚分配和接线方式。

## 1. 硬件清单

| 元件 | 型号 / 规格 | 说明 |
|---|---|---|
| 主控板 | NodeMCU ESP8266 (ESP-12E) | 4MB Flash，板载 USB-TTL（CH340/CP2102），提供 3V3 / GND 电源输出 |
| 目标芯片 | CC2530 模块（带 Zigbee 固件下载口） | TI 8051 内核 + 2.4GHz RF，Flash 256KB（CC2530F256） |
| 杜邦线 | 母对母 5 根 | 4 根信号线 + 1 根共地；3.3V 电源若模块已独立供电可省略 |
| USB 数据线 | Micro-USB | 给 NodeMCU 供电并烧录 ESP8266 固件 |
| 可选 | 万用表 / 示波器 | 用于排查接线问题（非必需） |

> 备注：CC2530 模块需引出 `RESETn`、`DC`、`DD`、`P0_3`、`VCC`、`GND` 共 6 个引脚。模块若已焊接在板子上，只要上述引脚可接触即可。

## 2. 引脚对照表

| ESP8266 GPIO | NodeMCU 丝印 | 方向 | CC2530 引脚 | 用途 |
|---|---|---|---|---|
| GPIO5  | D1  | → | Pin 7 (RESETn)   | CC Debug 复位信号 |
| GPIO4  | D2  | → | Pin 3 (DC)       | CC Debug 时钟（Data Clock） |
| GPIO12 | D6  | ↔ | Pin 4 (DD)       | CC Debug 数据（双向，Data Data） |
| GPIO3  | RX  | ← | P0_3 (UART0 TX)  | 监控用，接收 CC2530 串口日志 |
| GND    | GND | — | GND              | 共地（必须连接） |
| 3V3    | 3V3 | → | VCC              | 3.3V 电源（< 50mA） |

**方向说明**：
- `→` 表示信号由 ESP8266 输出给 CC2530
- `←` 表示信号由 CC2530 输出给 ESP8266
- `↔` 表示双向（DD 在写命令时为输出，读数据时切换为输入）
- `—` 表示参考电位

## 4. GPIO3 (RX) 复用说明

`GPIO3` 是 ESP8266 硬件 UART0 的 RX 引脚，与板载 USB-TTL 的 TX 共引脚。CCLoader 利用此特性实现"一脚两用"：

| 状态 | GPIO3 用途 | Serial 配置 | 说明 |
|---|---|---|---|
| **空闲态 (IDLE)** | 上位机串口（可选） | `Serial.begin(115200)` | 可输出 ESP8266 启动日志到 USB 串口监视器；WebUI 方案下上位机走 WiFi，不占用串口 |
| **烧录态 (BURNING)** | 不使用（CC Debug 走 DD/DC/RESET） | `Serial.begin(115200)` | 烧录过程不依赖 GPIO3，可保持 USB 串口日志输出 |
| **监控态 (MONITORING)** | 接收 CC2530 串口日志 | `Serial.end()` → `Serial.begin(<CC2530 波特率>)` | GPIO3 直接连到 CC2530 的 P0_3 (UART0 TX)，捕获启动日志和运行时输出 |

**状态切换流程**：

```
   IDLE (115200)
        │
        │ POST /api/monitor {baud, auto_reset}
        ▼
   Serial.end() → Serial.begin(baud)
        │
        ▼
   MONITORING (CC2530 波特率)
        │
        │ POST /api/stop
        ▼
   Serial.end() → Serial.begin(115200)
        │
        ▼
   IDLE (115200)
```

> 由于 WebUI 方案下上位机通过 WiFi 与 ESP8266 通信（不走 USB 串口），GPIO3 可以专门用于监控 CC2530 输出，无需在 USB 串口和 CC2530 串口之间手动切换。

## 5. 状态指示 LED

NodeMCU 板载蓝色 LED 连接在 `GPIO2 / D4` 引脚上（低电平点亮，但本固件采用简化的"高电平亮 / 低电平灭"语义，具体取决于板子硬件）。

固件中 `LED = 2`（对应 GPIO2 / D4），由 `ProgrammerInit()` 初始化为输出，烧录/监控时拉高，结束时拉低。

| LED 状态 | 含义 |
|---|---|
| 常灭 | 空闲（IDLE） |
| 常亮 | WiFi 已连接，等待操作 |
| 常亮（烧录中） | 烧录进行中（BURNING） |
| 常亮（监控中） | 监控进行中（MONITORING） |

> **简化实现**：进入烧录/监控时 LED 常亮，退出时熄灭。WiFi 连接状态请以 WebUI 顶部"IP"显示为准。

## 6. CC2530 供电说明

| 项目 | 参数 |
|---|---|
| 供电电压 | 3.3V（**严禁 5V**，会损坏 CC2530） |
| 供电来源 | NodeMCU 的 `3V3` 引脚 |
| 工作电流 | < 50mA（CC2530 + 外设典型值） |
| NodeMCU 3V3 输出能力 | 约 300mA（来自板载 AMS1117-3.3，由 USB 5V 降压） |
| 余量 | 充足（约 250mA 余量供 ESP8266 自身及外设使用） |

**注意事项**：
1. **必须共地**：NodeMCU 的 `GND` 与 CC2530 的 `GND` 必须连接，否则信号无参考电位，CC Debug 无法工作。
2. **电源稳定性**：若 CC2530 模块带 PA（功放，如 CC2530+CC2592），瞬时电流可能超过 100mA，建议独立供电并共地。
3. **不要从 USB 5V 直接接 CC2530**：会立即损坏芯片。
4. **上电顺序**：NodeMCU 上电后 3V3 稳定，再通过 GPIO 控制 CC2530，无顺序要求。

## 7. CC Debug 协议原理

CC2530 采用 TI 的 **CC Debug Interface**（2 线调试接口：DC + DD），加上 RESETn 共 3 根控制线。CCLoader 通过 ESP8266 的 GPIO **bit-bang（软件模拟时序）** 实现该协议，无需专用硬件。

### 7.1 引脚定义

| 信号 | 全称 | 方向 | 作用 |
|---|---|---|---|
| DC | Debug Clock | ESP8266 → CC2530 | 时钟信号，每个上升沿/下降沿传输 1 bit |
| DD | Debug Data | 双向 | 数据线，写命令时 ESP8266 输出，读数据时 CC2530 输出 |
| RESETn | Reset (active low) | ESP8266 → CC2530 | 复位信号，进入调试模式时需特定时序 |

### 7.2 时序原理（bit-bang 实现）

固件中 `write_debug_byte()` / `read_debug_byte()` 函数通过 `digitalWrite` / `digitalRead` 逐位收发：

```
写一个字节（8 bit）：
  for i = 0..7:
      DC = HIGH                  // 拉高时钟
      DD = (data & 0x80) ? 1 : 0 // 设置数据位（MSB first）
      data <<= 1
      DC = LOW                   // 拉低时钟，CC2530 在下降沿采样

读一个字节（8 bit）：
  for i = 0..7:
      DC = HIGH                  // 拉高时钟
      data <<= 1
      if (DD == HIGH) data |= 1  // 读取数据位（MSB first）
      DC = LOW                   // 拉低时钟
```

### 7.3 进入调试模式

`debug_init()` 函数通过以下时序让 CC2530 进入 CC Debug 模式：

```
1. DD = LOW, DC = LOW, RESET = LOW   // 拉低所有信号
2. delay(10ms)                       // 等待复位
3. DC = HIGH → LOW → HIGH → LOW      // DC 切换 2 次（握手）
4. RESET = HIGH                      // 释放复位
5. delay(10ms)                       // 等待 CC2530 进入调试模式
```

### 7.4 支持的调试命令

| 命令 | 代码 | 说明 |
|---|---|---|
| CMD_CHIP_ERASE | 0x10 | 擦除整个 Flash |
| CMD_WR_CONFIG | 0x19 | 写配置寄存器 |
| CMD_RD_CONFIG | 0x24 | 读配置寄存器 |
| CMD_READ_STATUS | 0x30 | 读状态寄存器 |
| CMD_RESUME | 0x4C | 恢复执行 |
| CMD_DEBUG_INSTR_nB | 0x54\|n | 执行调试指令（1/2/3 字节） |
| CMD_BURST_WRITE | 0x80 | 突发写入（批量传输） |
| CMD_GET_CHIP_ID | 0x68 | 读取芯片 ID |

### 7.5 烧录流程

```
1. debug_init()              // 进入调试模式
2. read_chip_id()            // 读取芯片 ID（0 表示未检测到）
3. RunDUP()                  // 复位 CC2530
4. debug_init()              // 重新进入调试模式
5. chip_erase()              // 擦除 Flash
6. RunDUP() + debug_init()   // 再次复位 + 进入调试
7. 切换外部晶振（XOSC）       // 写 CLKCONCMD = 0x80，等待 CLKCONSTA = 0x80
8. 写配置寄存器（0x22）       // 启用调试接口
9. 循环写入 512 字节块：
   a. write_flash_memory_block(buf, addr, 512)
   b. （可选）read_flash_memory_block 校验
10. RunDUP()                 // 复位 CC2530，运行新固件
```

> **性能说明**：bit-bang 方式受 ESP8266 GPIO 切换速度限制，256KB Flash 烧录约需 60-90 秒。固件每 16 块（约 0.8-1.6 秒）调用一次 `yield()` 喂狗，避免触发软件看门狗复位。

## 8. 烧录 ESP8266 时的注意事项

### 8.1 GPIO3 (RX) 必须拔掉

**问题**：当 GPIO3 (RX) 已连接到 CC2530 的 P0_3 (UART0 TX) 时，烧录 ESP8266 固件会失败，报错：

```
Failed to connect to ESP8266: Timed out waiting for packet header
```

**原因**：ESP8266 烧录固件时，下载器（esptool）通过 USB-TTL 与 ESP8266 的 UART0 通信（TX/RX）。GPIO3 是 UART0 的 RX，若 CC2530 同时在 P0_3 输出串口数据（即使 CC2530 没有主动发送，上电默认状态也可能输出干扰电平），会干扰 esptool 与 ESP8266 的握手。

**解决方法**：

| 操作 | 说明 |
|---|---|
| **拔掉 GPIO3 (RX) ↔ P0_3 的连接线** | 烧录前必须拔掉这一根线 |
| 其他 3 根线可保留不动 | RESETn / DC / DD 不影响 ESP8266 下载 |
| 烧录完成后重新接上 | 恢复监控功能 |

### 8.2 推荐使用 OTA 升级（免拔线）

首次用 USB 烧录后，后续固件升级**全部走 WiFi**，无需再拔线：

| 方式 | 命令 / 操作 |
|---|---|
| 浏览器上传 | 访问 `http://<ESP8266-IP>/update`，选择 `.bin` 文件，点 "Update" |
| curl 命令 | `curl -F "image=@.pio/build/nodemcuv2/firmware.bin" http://<ESP8266-IP>/update` |

OTA 升级特性：
- **LittleFS 保留**：`/config.json`、已上传的 BIN 文件全部不丢
- **配置不丢失**：WiFi 配置、监控波特率等保持
- **无需重启**：升级完自动重启
- **无鉴权**：局域网内任意设备可调用（与 API 一致）
- **升级期间**：约 10-30 秒 HTTP/SSE 暂不可用，浏览器会断连，重启后自动恢复

### 8.3 强制下载模式（备用方案）

若 OTA 无法启动（如固件损坏），可使用 NodeMCU 的硬件按钮：

1. 按住 **FLASH** 按键不放
2. 按一下 **RESET** 按键
3. 释放 **FLASH** 按键
4. 此时 ESP8266 进入强制下载模式，可重新烧录固件

### 8.4 烧录 ESP8266 步骤总结

```bash
# 1. 拔掉 GPIO3 (RX) ↔ P0_3 的连接线（重要！）

# 2. USB 连接 NodeMCU 到电脑，确认端口号（如 COM5）
#    Linux/Mac: /dev/ttyUSB0 或 /dev/cu.SLAB_USBtoUART

# 3. 编译 + 烧录
python -m platformio run -t upload --upload-port COM5

# 4. 烧录完成后，重新接上 GPIO3 (RX) ↔ P0_3

# 5. 后续升级走 OTA，无需再拔线
curl -F "image=@.pio/build/nodemcuv2/firmware.bin" http://<ESP8266-IP>/update
```

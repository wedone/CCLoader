# CCLoader 项目进展

> 本文件描述 CCLoader 项目的当前状态、已完成功能和已知问题。新 AI 接手项目时，请先读本文件。

---

## 1. 项目概述

把 NodeMCU ESP8266 升级为 CC2530 烧录+监控一体机。

基于 RedBearLab CCLoader（2013-2014 年原始 CCLib 协议实现）改造，自 2026-07-20 起为 WebUI 烧录+监控一体机版本。浏览器访问 ESP8266 的 IP，即可上传 BIN/HEX、一键烧录、实时查看 CC2530 串口日志，全程无需拔插任何线。

## 3. 已完成功能（按版本组织）

### v1.0（2026-07-20）— WebUI 改造首版

- 基于 CCLib 的 CC2530 烧录工具 WebUI 化：ESP8266 (NodeMCU) 作为 WiFi 烧录+监控一体机
- **WiFi 配网**：AP 模式 captive portal + STA 模式切换，支持扫描周围网络
- **文件上传**：支持 .bin 直接烧录和 .hex 自动转换（浏览器端 hex2bin，填充到 256KB）
- **异步烧录**：`POST /api/burn` 立即返回 `task_id`，进度通过 SSE 实时推送
- **串口监控**：Serial 切换到 CC2530 波特率，接收 P0_3 日志并通过 SSE 推送
- **OTA 升级**：ESP8266HTTPUpdateServer 支持 WiFi 远程升级固件
- Agent 友好 API：异步烧录、`/api/monitor/buffer?since=N` 断点续传、8KB 环形缓冲
- 内嵌静态资源：`web_assets.h` 由 `tools/gen_web_assets.py` 从 `data/` 生成

### v1.1（2026-07-23）— OTA 分体固件烧录

- **OTA 分体固件烧录模式**：烧录页支持"单文件 / OTA 分体固件"切换，前端合并 Boot.hex + App.hex 为 256KB BIN（方案 A：前端合并，后端零改动）
- **烧录完成重启烧录器选项**：烧录卡片增加 `reboot-burner-check` 复选框
- **API 拒绝 .hex 直传**：`/api/upload` 收到 .hex 时返回 400 + `hint` 字段（含 hex2bin 算法说明）
- **NTP 网络授时（北京时间 UTC+8）**：WiFi 连接成功后 `configTime`，LittleFS 文件时间戳不再显示 1970
- 移除烧录完成后自动跳转监控页的行为
- `handleBurn` 移除同步分支，一律返回 202 + `task_id`（强制异步烧录）
- 修复 AI 调用 API 假死/反应慢（监控 loop 占用 CPU、同步烧录阻塞 HTTP、堆碎片化）

### v1.2（2026-07-23）— 监控模块通用化

- **监控模块通用化**：`resetCC2530()` 移除调试专用的 DD/DC 拉低操作，只操作 RESETn 一根线
- **`auto_reset` 默认改为 `false`（非侵入式监听）**：后端默认不再自动复位目标设备
- 监控中手动复位 CC2530 时保留累计计数，保证 Agent 断点续传 offset 语义单调递增
- 修复跨 tailscale 访问 WebUI 大响应截断（新增 `sendChunked_P()` 分块发送，单 TCP 段 < 1280 字节）
- **`gen_web_assets.py` 换行符导致 `sizeof` 与 `_len` 不匹配**：生成时统一去除 `\r`

### v1.3（2026-07-26）— 清除配网 + 备份固件

- **清除 CC2530 配网信息**：`POST /api/nvreset` 读取 Flash → 清除尾部 4KB NV 区域 → 全片擦除 → 写回，保留固件仅清除 Zigbee 配网（约 2 分钟）
- **备份 CC2530 固件**：`POST /api/backup` 读取 CC2530 全部 Flash（256KB）保存到 LittleFS，生成 `backup_YYYYMMDD_HHMMSS.bin`（约 1 分钟）
- `BurnState` 结构新增 `info` 字段，SSE 推送操作结果信息（如备份文件名）
- 帮助页 FAQ 新增"清除配网"和"备份固件"说明
- **移除两个无效复选框**：烧录后校验（后端强制 verify=true）、烧录后复位（`burnFromLittleFS` 末尾已 `RunDUP()` 复位过）
- **帮助页渲染升级**：从纯文本 `<pre>` 改为零依赖轻量 markdown HTML 渲染（约 80 行 `renderMarkdown()`）
- 烧录完成日志由"烧录完成"改为通用的"操作完成"
- 备份完成后自动刷新文件列表

## 6. 已知问题 / 限制

| 项 | 说明 |
|---|---|
| 仅支持 ESP8266 | 不兼容 ESP32（使用 ESP8266 特有的 `ESP8266WebServer`/`LittleFS`/`WiFiServer` API） |
| WiFi 仅 2.4GHz | ESP8266 硬件限制，不支持 5GHz |
| SSE 最大 4 个并发客户端 | `SSE_MAX_CLIENTS = 4`，第 5 个连接被拒绝 |
| BIN 文件 ≤ 256KB | LittleFS 1MB 分区可用约 700KB，CC2530F256 物理容量 256KB |
| 无鉴权 | 局域网内任意设备可调用所有 API（与 OTA 升级一致） |
| `/api/config` 的 `verify` 字段 | 后端仍返回但前端不再读取（后端强制 verify=true，不影响功能） |

## 7. 项目结构

项目目录简要结构如下（详细说明请参考根目录 `项目文档索引.md`）：

```
D:\VC\CCLoader\
├── src\
│   └── CCLoader.ino          # ESP8266 固件主文件（CC Debug 协议 + WebUI）
├── data\                      # WebUI 静态资源源目录
│   ├── index.html             # WebUI 主页（三标签 SPA）
│   ├── style.css              # 暗色主题响应式样式
│   ├── app.js                 # 前端逻辑（SSE + fetch API）
│   ├── help.md                # 帮助页 markdown 源（由 /api/help 返回）
│   └── config.json            # 默认配置
├── tools\
│   └── gen_web_assets.py      # 由 data/ 生成 src/web_assets.h（内嵌静态资源）
├── platformio.ini             # PlatformIO 编译配置（无 lib_deps）
├── CHANGELOG.md               # 更新日志（Keep a Changelog 格式）
├── README.md                  # 操作教程
└── Documents\                 # 项目文档目录
```

**核心代码模块（`src/CCLoader.ino`）**：
- CC Debug 协议层：`write_debug_byte` ~ `RunDUP`（原 RedBearLab 代码，保持不变）
- WebUI 层：`ESP8266WebServer` (端口 80) + 原生 `WiFiServer` SSE (端口 81)
- 文件系统：LittleFS（存储 BIN、配置、备份）
- 状态机：IDLE / BURNING / MONITORING 三态互斥

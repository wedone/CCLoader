本文件描述 CCLoader 烧录器的编译、烧录和 OTA 升级流程。

---

## 1. 开发环境

| 组件 | 说明 |
|---|---|
| PlatformIO Core | 命令行版本，`pip install platformio` 安装 |
| VSCode PlatformIO IDE 插件 | 图形化版本，[安装地址](https://marketplace.visualstudio.com/items?itemName=platformio.platformio-ide) |
| Python 3 | 运行 PlatformIO Core 与 `tools/gen_web_assets.py` 资源生成器 |

> 以下命令以 PlatformIO Core 为例（`python -m platformio ...`）。使用 VSCode 插件时，对应命令可在 PIO 侧边栏通过点击按钮执行（Build / Upload / Serial Monitor）。

目标平台：NodeMCU ESP8266（ESP-12E，4MB Flash），平台配置见 `platformio.ini`：

- `platform = espressif8266@4.2.0`
- `board = nodemcuv2`
- `framework = arduino`
- 文件系统：`littlefs`，链接脚本 `eagle.flash.4m1m.ld`
- **无外部库依赖**（`lib_deps` 为空），全部使用 ESP8266 Arduino Core 自带功能

## 2. 项目结构说明

```
D:\VC\CCLoader\
├── src\
│   ├── CCLoader.ino          # ESP8266 固件主文件（CC Debug 协议 + WebUI + SSE + LittleFS）
│   └── web_assets.h          # 自动生成的内嵌静态资源（PROGMEM，禁止手动编辑）
├── data\                      # WebUI 静态资源源文件
│   ├── index.html             # WebUI 主页（三标签 SPA，含版本号字符串）
│   ├── style.css              # 暗色主题响应式样式
│   ├── app.js                 # 前端逻辑（SSE + fetch API）
│   ├── config.json            # 默认配置
│   └── help.md                # 帮助文档（WebUI 帮助页 + AI Agent 共用）
├── tools\
│   └── gen_web_assets.py      # 静态资源生成器（data/ → src/web_assets.h）
├── platformio.ini             # PlatformIO 编译配置
└── README.md                  # 项目主文档
```

### 2.1 关键文件说明

| 文件 | 作用 |
|---|---|
| `src/CCLoader.ino` | 固件主程序，包含 CC2530 烧录协议、HTTP 服务器（端口 80）、SSE 实时推送（端口 81）、状态机、配网逻辑 |
| `data/` | WebUI 前端源文件，**修改后必须重新生成 `web_assets.h` 并重新编译** |
| `tools/gen_web_assets.py` | 读取 `data/` 下 5 个文件（index.html / style.css / app.js / config.json / help.md），用 raw string literal 编码为 `src/web_assets.h`（PROGMEM 内嵌），OTA 升级时随固件一并更新 |
| `src/web_assets.h` | **自动生成**，不要手动编辑。命名空间 `WebAssets`，导出 `index_html` / `style_css` / `app_js` / `config_json` / `help_md` 及对应的 `_len` 长度变量 |

## 3. 编译流程

在项目根目录 `D:\VC\CCLoader\` 执行：

```bash
python -m platformio run
```

看到 `SUCCESS` 即编译成功。

**输出产物**：

```
.pio/build/nodemcuv2/firmware.bin
```

> 首次编译会自动下载 `espressif8266@4.2.0` 平台包，需要联网。若网络受限，可设置 PlatformIO 镜像或离线包。

## 4. 首次烧录（USB）

### 4.1 烧录命令

把 NodeMCU 用 USB 数据线接到电脑，假设识别为 `COM5`：

```bash
python -m platformio run -t upload --upload-port COM5
```

> Linux/Mac 用户端口名形如 `/dev/ttyUSB0` 或 `/dev/cu.SLAB_USBtoUART`。

### 4.2 烧录前必做：拔掉 GPIO3 (RX) 连线

> **关键注意事项**：若 NodeMCU 的 GPIO3 (RX) 已接 CC2530 的 P0_3，烧录/上传前**必须先拔掉这根线**。
>
> 原因：GPIO3 与 USB-TTL 的 TX 共引脚，CC2530 的串口输出会干扰 ESP8266 的下载通信，导致 `Failed to connect to ESP8266: Timed out waiting for packet header` 错误。
>
> 其他 3 根线（RST / DC / DD）可保留不动。

### 4.3 强制下载模式（备用）

若拔线后仍无法烧录，按住 NodeMCU 的 **FLASH** 按键 + 按 **RESET** 复位，进入强制下载模式后松开 FLASH，再执行烧录命令。

## 5. OTA 远程升级（推荐）

首次用 USB 烧录后，后续固件升级**全部走 WiFi**，无需再拔 TX 线。这也是修改 WebUI 后的标准发布方式。

### 5.1 方式 A：浏览器上传

1. 浏览器访问 `http://<ESP8266-IP>/update`（如 `http://10.0.0.147/update`）
2. 选择本地编译产物 `.pio/build/nodemcuv2/firmware.bin`
3. 点 "Update" → 等待 10-30 秒 → 自动重启

### 5.2 方式 B：curl 命令

```bash
curl -F "image=@.pio/build/nodemcuv2/firmware.bin" http://10.0.0.147/update
```

返回 `Update Success: ...` 表示成功，ESP8266 自动重启加载新固件。

### 5.3 OTA 特性

| 特性 | 说明 |
|---|---|
| LittleFS 保留 | `/config.json`、已上传的 BIN 文件全部不丢 |
| 配置不丢失 | WiFi 配置、监控波特率等保持 |
| 自动重启 | 升级完成后自动重启加载新固件 |
| 无鉴权 | 局域网内任意设备可调用（与 API 一致） |

> 升级期间（约 10-30 秒）HTTP / SSE 暂不可用，浏览器会断连，重启后自动恢复。

## 6. WebUI 静态资源更新流程（关键！）

修改 `data/` 目录下任何文件后，**必须**按以下步骤发布，否则页面不会生效。

### 6.1 标准流程

```bash
# 1. 修改 data/ 下的源文件（index.html / style.css / app.js / config.json / help.md）
# 2. 重新生成内嵌资源头文件
python tools/gen_web_assets.py

# 3. 编译固件
python -m platformio run

# 4. OTA 升级（IP 替换为实际地址）
curl -F "image=@.pio/build/nodemcuv2/firmware.bin" http://10.0.0.147/update
```

### 6.2 重要约束

- ⚠️ **`src/web_assets.h` 是自动生成的，禁止手动编辑**。任何前端修改都通过 `data/` → `gen_web_assets.py` → `web_assets.h` 的路径流转。
- ⚠️ **版本号必须通过 `gen_web_assets.py` 自动同步**，不要在 `web_assets.h` 里手改版本字符串。
- `gen_web_assets.py` 会读取 `data/` 下 5 个文件，用 raw string literal (`R"=====( ... )====="`) 编码为 PROGMEM 常量。若任一文件包含分隔符 `)=====(` 会报错退出。
- 生成器会统一换行符为 `\n`（去除 `\r`），避免 GCC 编译 raw string 时 `sizeof` 与 `_len` 不匹配导致 `Content-Length` 头错误。

### 6.3 旧版 uploadfs 方式（已废弃）

> 新版固件（commit 439a693 之后）已将 WebUI 静态资源内嵌到固件中（PROGMEM），OTA 升级即可更新页面，**无需 uploadfs**。
>
> 旧版固件仍可通过 `python -m platformio run -t uploadfs --upload-port COM5` 上传到 LittleFS。新项目请使用上述 6.1 流程。

## 7. 版本号位置

WebUI 版本号字符串固定写在前端源文件，由生成器自动同步到固件。

### 7.1 源头：`data/index.html`

文件中（约第 163 行）有一行固件版本显示：

```html
<div>固件版本: CCLoader-WebUI v1.x</div>
```

修改版本号时，**只改 `data/index.html` 这一处**即可。

### 7.2 同步：`src/web_assets.h`

`tools/gen_web_assets.py` 运行后，`index.html` 的内容（含版本字符串）会被原样内嵌到 `web_assets.h` 的 `WebAssets::index_html` 常量中。固件运行时通过 `WebServer` 直接 PROGMEM 返回，浏览器显示的版本号即来自此处。

### 7.3 验证版本一致性

编译前可用以下命令快速核对版本号是否同步：

```bash
# 查看源文件版本
python -c "import re; print(re.search(r'CCLoader-WebUI v1\.\d+', open('data/index.html',encoding='utf-8').read()).group())"

# 查看生成头文件版本（应与上面一致）
python -c "import re; print(re.search(r'CCLoader-WebUI v1\.\d+', open('src/web_assets.h',encoding='utf-8').read()).group())"
```

> 若两者不一致，说明 `web_assets.h` 未重新生成，运行 `python tools/gen_web_assets.py` 即可。

## 8. 串口监视器

### 8.1 启动命令

```bash
python -m platformio device monitor -p COM5 -b 115200
```

波特率 115200 对应 `platformio.ini` 中的 `monitor_speed = 115200`。

### 8.2 监控模式下的串口行为

| 设备状态 | Serial 行为 | USB 串口监视器显示 |
|---|---|---|
| 空闲 / 烧录态 | 115200 | 正常显示 ESP8266 启动日志 |
| 监控态（WebUI 进入监控） | `Serial.end()` → `Serial.begin(CC2530 波特率)` | 显示 CC2530 串口日志的乱码（波特率不同） |
| 退出监控 | 自动恢复 115200 | 恢复正常 |

> 由于 WebUI 方案下上位机通过 WiFi 与 ESP8266 通信（不走 USB 串口），GPIO3 可以专门用于接收 CC2530 P0_3 的串口日志，USB 串口仅用于调试 ESP8266 启动信息。

### 8.3 启动日志示例

```
CCLoader WebUI booting...
Config mode (no config): AP 'CCLoader-Setup' open, IP: 192.168.4.1
CCLoader WebUI ready
HTTP: 80, SSE: 81
Trying connect to MyWiFi ...
Connected, IP: 192.168.1.100
```

## 9. 常见编译错误

### 9.1 编译期错误

| 问题 | 原因 | 解决 |
|---|---|---|
| `UnknownPackageError: Could not find the package with 'WebSockets'` | 旧版本 `lib_deps` 仍引用外部库 | 已移除，重新拉取最新代码或确认 `platformio.ini` 中无 `lib_deps` |
| `'UriRegex' was not declared` | 未包含头文件 | 已在源码顶部 `#include <uri/UriRegex.h>`，确认源码完整 |
| `LittleFS mount failed!` | LittleFS 未格式化 | 首次烧录固件后通常会自动处理；旧版需执行 `uploadfs` |
| `platforms.lock` 沙箱阻止 | PlatformIO 试图写用户目录 | 用管理员权限运行，或检查杀毒软件白名单 |

### 9.2 烧录期错误

| 问题 | 原因 | 解决 |
|---|---|---|
| `Failed to connect to ESP8266: Timed out waiting for packet header` | GPIO3 (RX) 接到 CC2530 P0_3，CC2530 输出干扰 ESP8266 下载 | **拔掉 GPIO3 ↔ P0_3 的连接线后重试**；或按住 FLASH + RESET 进入强制下载模式 |

### 9.3 排查建议

1. 烧录失败优先检查 GPIO3 (RX) 是否已拔掉。
2. 编译失败优先确认 `platformio.ini` 中 `lib_deps` 为空（本项目无外部库依赖）。
3. 网络受限导致平台包下载失败时，配置 PlatformIO 镜像源或使用离线包。
